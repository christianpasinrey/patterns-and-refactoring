# Quarkus · Micronaut · Java

[← back to router](../framework-idioms.md)

Checked against Quarkus 3.40 LTS and Micronaut 5.2 (October 2026). For Spring, see
[spring-java.md](spring-java.md): the vocabulary looks alike, the rules below do not.

## What Quarkus and Micronaut already give you

Both move framework work out of startup: Quarkus into a build step, Micronaut into annotation
processors. Most of what follows is the same pattern as in Spring with a different cost.

| Pattern | Where it already lives | Do this, not that |
|---|---|---|
| **Abstract Factory + DI** | Quarkus ArC (implements CDI Lite); Micronaut `micronaut-inject-java` processor | Constructor injection. ArC needs no `@Inject` on a sole constructor. Private fields cost reflection in both: ArC rewrites them by default, Micronaut warns against them |
| **Factory Method** | `@Produces`; Micronaut `@Factory` + `@Bean` | Use for third-party types you cannot annotate. A producer defaults to `@Dependent`, so a new instance per injection point unless you scope it |
| **Singleton** | `@ApplicationScoped` (lazy, client proxy); `@Singleton` (no proxy, created when injected). Micronaut `@Singleton`, lazy by default; `@Context` is eager | Never a static instance. In Quarkus, `@Singleton` trades lazy creation and `QuarkusMock` for having no proxy; pick it only if you want that trade |
| **Strategy** | `@All List<T>`, `Instance<T>` + `@Identifier`; Micronaut collection injection + `@Named` | Requires two real variants. Micronaut collections are unordered until you add `Ordered` or `@Order` |
| **Fallback implementation** | `@DefaultBean`; Micronaut `@Replaces` + `@Requires` | Fits libraries that let an application override a default. Inside one application it is indirection |
| **Chain of Responsibility** | `@ServerRequestFilter` / `@ServerResponseFilter`; Micronaut `@ServerFilter` + `@RequestFilter` | Quarkus pre-matching filters always run on the event loop, so no blocking calls there. Response filters skip streamed responses |
| **Decorator** | CDI `@Decorator` + `@Delegate`; Micronaut `@Around` + `MethodInterceptor` | CDI decorators wrap interface types and cannot wrap built-ins such as `Event`. One decorator on one bean is a method call in disguise |
| **Proxy** | CDI client proxies; Micronaut compile-time `$Intercepted` subclass | Client proxies forward methods only, so never read a field of a normal-scoped bean directly |
| **Observer** | `Event<T>` + `@Observes` / `@ObservesAsync`; Micronaut `ApplicationEventPublisher` + `@EventListener`, `@TransactionalEventListener` (Micronaut Data) | Plain Micronaut listeners run before commit, so they may react to work that later rolls back. Use the transactional listener for side effects. `fire()` is synchronous: a slow observer slows the caller |
| **Unit of Work** | `@Transactional` around Hibernate | Put it on the entry point. In Quarkus REST it also marks the method as blocking, and Panache flushes at commit or before a query |
| **Data Mapper** | Hibernate ORM; Micronaut Data JDBC | Micronaut Data JDBC does no lazy loading: fetch plans are declared up front with `@Join`, which is more typing and no accidental N+1 |
| **Active Record** | `PanacheEntity`, `PanacheEntityBase` | See the decision below |
| **Repository** | `PanacheRepository`; Micronaut Data `@Repository` interfaces | Micronaut fails compilation when a repository method cannot be implemented, not at request time. A repository interface wrapping another one adds a layer and no check |
| **Specification** | Micronaut Data `JpaSpecificationExecutor` | Only for queries that cannot be defined at compile time: you give up the compile-time check for that query |
| **Retry / Circuit Breaker** | `@Retry`, `@CircuitBreaker`, `@Timeout`, `@Fallback` (`quarkus-smallrye-fault-tolerance`); Micronaut `@Retryable`, `@CircuitBreaker` | Declarative. Only on idempotent work: a retry repeats the side effect. Micronaut's default is three retries with a one-second linear delay |
| **Cache-Aside** | `@CacheResult`, `@CacheInvalidate`; Micronaut `@Cacheable` | Quarkus forbids private methods here and caches `null`, so a miss can stick |
| **Scheduler** | `@Scheduled` in both | Quarkus runs overlapping executions by default. `concurrentExecution = SKIP` guards one instance only, never a cluster |
| **Configuration** | `@ConfigProperty`; Micronaut `@ConfigurationProperties` (reflection-free) | In Quarkus each property is build-time or runtime. Changing a build-time one in production does nothing except a warning |

## Build-time DI vs Spring's runtime model

| | Spring Boot 4.1 | Quarkus 3.40 | Micronaut 5.2 |
|---|---|---|---|
| **Bean metadata** | Parsed at runtime on the JVM; generated by AOT for native | Processed once during build-time augmentation | Computed by annotation processors at compile time |
| **Proxies** | Generated at runtime on the JVM | Generated at build time | Generated at compile time, as subclasses |
| **Conditional beans** | `@ConditionalOnProperty` works on the JVM, restricted in native | `@IfBuildProfile` decided at build; `@LookupIfProperty` at runtime lookup | `@Requires` on classpath, config or other beans |

The saving is startup time and memory. The price is that the framework has already seen your
code, so anything discovered later does not exist. What this forbids:

- **CDI portable extensions.** Quarkus cannot support them. Port to a Quarkus extension, which is real work.
- **Runtime classpath scanning for beans.** A bean in a dependency needs a Jandex index or `beans.xml` in Quarkus. In Micronaut it must be processed, or brought in with `@Import`, which sees only scoped or qualified classes unless told otherwise.
- **Unseen lookups.** ArC removes unused beans at build time and cannot see `CDI.current()`, so the bean it asks for may be gone. Mark it `@Unremovable`, and treat each one as a smell.
- **Build profile switches at deploy time.** `@IfBuildProfile` ignores the runtime profile. A flag that must flip per environment after the build belongs in `@LookupIfProperty` or plain config.
- **Private intercepted methods.** ArC fails the build on an interceptor binding on a private method. Micronaut overrides only non-final, non-private methods.
- **Final classes under Micronaut advice.** Advice is a compile-time subclass, and Kotlin classes are final by default. KSP needs extra configuration to see the all-open plugin.

Micronaut's replacement rule also differs. Beans have a type and qualifier, not a name or load
order, so a same-named bean never overrides anything. Override with `@Replaces`, explicitly.

**Do not port the Spring self-invocation workaround.** ArC intercepts a call from a bean to its
own intercepted method, as a non-standard feature. The CDI specification leaves this undefined,
so it does not carry to other CDI containers. Moving a method to a second bean purely to
trigger `@Transactional` is unneeded here.

## Panache: Active Record or Repository

The two styles expose the same operations. The difference is where they sit.

```java
@Entity public class Person extends PanacheEntity {     // Active Record
    public String name;
    static List<Person> named(String n) { return list("name", n); }
}

@ApplicationScoped class PersonRepository               // Repository
    implements PanacheRepository<Person> {
    List<Person> named(String n) { return list("name", n); }
}
```

**Active Record is justified when:**

- The service is CRUD-shaped and rules are few. This is the style most of the guide's examples use, and the one with the least code.
- You accept `quarkus-panache-mock` for tests, because static methods cannot be mocked with plain Mockito.

**Not justified when:**

- The domain must not depend on the framework: `extends PanacheEntity` puts Panache in every entity.
- Tests need to replace data access per bean. Static methods take a dedicated mock helper; a repository takes `@InjectMock`.

**Repository is justified when:**

- Entities are plain JPA and must stay so, or queries need a named home separate from the model.
- The team already works this way. Mixing both styles in one service gives two places to look.

**Not justified when:**

- It only forwards to the entity, or it is a second interface over `PanacheRepository`. That is Middle Man.

**Micronaut skips this argument.** Micronaut Data is organised around repository interfaces,
implemented at compile time, so the default answer is an interface.

**Quarkus Data Hibernate** (formerly Panache Next) is a newer, separate extension with
`ManagedEntity`, `RecordEntity` and Jakarta Data repositories. Its docs mark it experimental,
class and package names included, so build on it only if you can absorb renames.

See [enterprise-patterns.md](../enterprise-patterns.md#data-source-architecture).

## Native image constraints

GraalVM assumes a closed world: it keeps only what the call tree reaches and drops the rest.

- **Reflection** must be declared: `@RegisterForReflection` in Quarkus; `@ReflectiveAccess`, `@TypeHint` or `@ReflectionConfig` in Micronaut. Without it, a JSON library may fail, or silently emit empty output.
- **Resources** beyond `META-INF/resources` need `quarkus.native.resources.includes`.
- **Runtime proxy generation is not supported.** Dynamic proxies are declared at build time with `@RegisterForProxy`.
- **Quarkus initialises all classes at build time by default.** A static field holding the clock or a `Random` is frozen into the image. Keep such state in a bean's instance fields, or delay it with `--initialize-at-run-time`.
- **Groovy is out** for Micronaut native builds: only Java and Kotlin are supported.

**Worth the cost when** startup and memory are the problem: scale-to-zero, short-lived functions.
**Not worth it when** a service runs for weeks. Quarkus's guide quotes a 3 to 10 minute build on
4 to 8 GB of RAM, against seconds for a JVM build, and `@QuarkusIntegrationTest` exercises the
native executable only through its HTTP endpoints. Stay on the JVM until a number says otherwise.

## Framework features that replace patterns

| Feature | Replaces |
|---|---|
| **`@Interceptor` + `@InterceptorBinding`** | Hand-written wrapper classes for cross-cutting work. Each binding is hidden control flow, so reserve them for concerns that really cross beans |
| **`@ServerExceptionMapper`** | Try/catch in every endpoint. In an endpoint class it covers only that class |
| **Micronaut `@Client`** | Hand-written HTTP adapters; implemented at compile time from an interface |
| **Micronaut `@EachProperty` / `@EachBean`** | A factory that builds one client per config block |
| **Micronaut Data `@Query`** | A custom DAO for one query; the `Page` form needs a count query or compilation fails |
| **`@QuarkusIntegrationTest`** | Hand-rolled packaging smoke tests, within the HTTP-only limit above |

Records, sealed interfaces and virtual threads work here too; see
[spring-java.md](spring-java.md#java-language-features-that-replace-patterns).

## Signs you are fighting the framework

- `CDI.current()` or `BeanContainer` lookups scattered through business code.
- A wall of `@Unremovable` or `quarkus.arc.remove-unused-beans=false` to make startup behave.
- Reflection-based libraries added to a native build, each with its own hint file. A build-time alternative usually costs less.
- A static singleton or static cache in code compiled to native.
- A second bean created only to trigger an interceptor, copied from Spring habits.
- `@IfBuildProfile` used for a value that differs per deployment.
- Field injection into private fields in Micronaut.
- A service class that only forwards to `PanacheRepository`.
- Interceptor bindings on private methods, or Micronaut advice on final methods, expecting them to fire.
